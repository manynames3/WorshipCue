Implemented 2026-10-08 on branch `v2`, Build **4**, app marketing version **0.0.1**,
minimum **iPadOS 16.0**. This is a development checkpoint, not an App Store release
or an end-user readiness claim. V1 is preserved at

## Implemented behavior

- Light native reader with a compact song/version/key/local-save header, a large
  PDF surface, local page controls and vertical annotation tools.
- Persistent Today, Library and Stand navigation; bottom navigation at narrow
  widths. Preparation cards and searchable song rows use the existing local
  setlist/library actions and real bounded PDF thumbnails.
- Small eight-color popover with separate remembered pen/highlighter choices;
  visible Pencil/touch input control with an explicit close action.
- Charcoal version/notes inspector docked at widths of at least 1,000 points and
  heights of at least 500 points; dismissible sheet at smaller sizes. Actual chart
  versions and keys, independent open/prefer controls, exact source PDF/ink
  preview, explicit destination page, manual drag/uniform scale/cancel/confirm,
  and pinned source-preservation lock/info.
- Existing immutable PDF assets, owner/version/page ink identities, bookmarks,
  transactional saves, weekly packet extraction, setlist edits and fallback
  export are reused. No storage migration, production dependency or backend was
  introduced. The existing app bundle and approved app icon are retained.

The concept's future announcement strip and team mismatch state have no live
backing service yet. No automatic song changes, page synchronization, automatic
note transfer/merging or PDF transposition was added. Git development v1/v2 labels
are distinct from numbered chart versions inside the app.
