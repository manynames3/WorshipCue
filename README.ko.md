# WorshipCue

**우리 교회의 악보와 편곡을 모으고, 매주 예배에서 함께 꺼내 쓰는 공간.**

WorshipCue는 교회 찬양팀이 자주 사용하는 PDF 악보와 수정한 편곡을 보관하고, 팀과 공유하며, 예배 순서에 맞춰 준비하고 연주할 수 있도록 개발 중인 iPad 앱입니다. 한국어 찬양팀을 위한 **공유 악보 아카이브, 주간 예배 준비, 개인 악보장**을 하나의 흐름으로 연결하는 것이 목표입니다.

[English](README.md) · [현재 검증 결과](verification/M1.md) · [개발 계획](docs/12_BUILD_PLAN.md)

## 왜 만들고 있나요?

찬양팀에는 그 교회가 자주 부르는 곡과 익숙한 편곡이 쌓입니다. 브리지 반복 횟수, 보컬 진입, 건반 보이싱, 쉬어야 할 마디처럼 함께 준비하며 정한 내용도 있습니다. 그러나 다음에 같은 곡을 할 때 지난 악보를 다시 찾고, 어떤 수정본을 썼는지 확인하고, 이번 주 순서에 맞춰 PDF를 다시 묶어야 합니다.

WorshipCue의 중심은 **우리 교회가 쌓아 온 악보와 편곡을 다음 예배에서도 쉽게 찾아 함께 쓰는 것**입니다. 대화는 카카오톡을 그대로 써도 됩니다. 또 하나의 채팅방을 만드는 대신, 반복해서 사용할 자료와 이번 예배의 준비를 한곳에 연결하려는 것입니다.

예배 현장까지 이어져야 합니다. 준비한 악보를 iPad에서 읽고 메모하며, 예정에 없던 곡이 나와도 팀이 필요한 악보를 확인할 수 있어야 합니다. 동시에 밴드마스터의 안내가 연주자의 현재 악보나 페이지를 강제로 바꾸어서는 안 됩니다.

첫 사용자는 한국어 찬양팀의 연주자와 보컬, 주간 악보를 준비하는 담당자, 특히 건반을 연주하며 팀을 이끄는 밴드마스터입니다.

## 팀의 준비부터 예배 현장까지

| 이런 순간에 | 제공하려는 경험 | 현재 상태 |
|---|---|---|
| 지난번에 썼던 우리 교회 편곡을 찾고 싶어요. | 자주 쓰는 곡과 수정본을 모아 검색하고, 이전 버전과 메모를 다시 찾습니다. | 로컬 검색·즐겨찾기·버전·기본 악보 선택 구현. 교회 팀 라이브러리와 기기 간 공유는 예정. |
| 이번 주 악보를 순서대로 준비해 나누고 싶어요. | 예정곡·대기곡·키·버전을 정하고, 여러 곡을 하나의 주간 PDF로 묶어 공유합니다. | 로컬 주간 목록과 기존 PDF의 곡별 분리 구현. 현재 PDF 내보내기와 세트 전체 합본 생성은 별개이며, 합본은 구현·검증 예정. |
| 새 악보가 왔는데 이전 필기가 필요해요. | 원본과 필기를 남겨 두고 필요한 획만 선택해 새 악보에 옮깁니다. | 버전·페이지별 저장과 수동 선택 복사/붙여넣기 구현. 새 대상 선택 패널의 최종 UI 검증은 남아 있음. |
| 밴드마스터가 후렴에 동그라미를 쳤어요. | 개인 메모와 분리된 팀 필기를 보고, 다른 버전이면 팀 악보를 미리봅니다. | 읽기 전용 로컬 예시 구현. 실제 팀 손필기 공유와 서버 권한 검증은 예정. |
| 예배 중 예정에 없던 곡으로 넘어가요. | 라이브러리에서 찾거나 없는 PDF를 권한 있는 사용자가 올려 준비합니다. 밴드마스터가 곡·키를 안내하면 각자 직접 눌러 엽니다. | 실시간 안내·공유는 구현 예정. 현재 실시간 서버는 없음. |
| 리허설 중 인터넷이 끊겼어요. | 기기에 있는 악보를 계속 읽고 개인 메모를 로컬에 저장합니다. | 로컬 읽기·저장·복구와 파일 확인 구현. 서버 다운로드·동기화·재연결 검증은 후속 단계. |

## 지금 사용할 수 있는 기능

현재 앱은 **M1 로컬 안정성 개발 빌드**입니다. 실제 iPad에 로컬 설치해 테스트했으며, App Store 출시나 완성된 교회 파일럿은 아닙니다.

- **PDF 읽기와 가져오기:** 파일 앱에서 가져온 PDF를 검증해 앱 내부에 보관합니다. 가져오기 실패가 현재 읽고 있는 악보를 바꾸지 않습니다.
- **주간 예배 준비:** 예정곡과 대기곡을 담은 목록을 만들고, 곡마다 사용할 악보 버전과 연주 키를 정합니다. 같은 곡을 여러 순서에 넣고 목록을 복사하거나 순서를 바꿀 수 있습니다.
- **한국어 라이브러리:** 제목·초성·별칭·찬송가 번호 검색과 즐겨찾기. 악보 열기와 개인 기본 악보 지정은 별도 동작입니다.
- **기존 주간 PDF 나누기:** 시작·끝 페이지를 직접 지정해 곡별 PDF를 만듭니다. 원본과 편곡자의 PDF 주석은 보존합니다.
- **현재 PDF 내보내기:** 원본·편곡자 내용과 선택한 개인 필기로 새 PDF를 만들어 공유하거나 파일 앱에 저장합니다. 원본은 덮어쓰지 않습니다. 세트 전체 합본이나 실제 공유 팀 필기 내보내기를 뜻하지 않습니다.
- **개인 필기:** 펜, 형광펜, 획 지우개, 실행 취소, 다시 실행. Apple Pencil 연결 구조가 구현되어 있으며, 화면의 **손가락 필기** 모드로 터치 필기를 사용할 수 있습니다. 실물 Apple Pencil 검증은 남아 있습니다.
- **작은 색상 팝업:** 도구 옆 색상 원을 누르면 8개 색상이 나타납니다. 색상 선택, ×, 팝업 바깥 탭으로 닫을 수 있습니다. 펜과 형광펜은 각자 선택한 색상을 기억합니다.
- **정확한 악보에 저장:** 개인 메모는 버전과 페이지에 연결됩니다. ‘기기에 저장됨’은 실제 로컬 데이터베이스 저장 이후 표시합니다.
- **선택한 필기만 이동:** 사각형으로 선택 → 복사 → 대상 악보·페이지 선택 → 붙여넣기 미리보기 위치·크기 조정 → 확정 또는 취소. 원본 메모는 그대로 남습니다.
- **내 페이지 유지:** 페이지는 각자 넘깁니다. 앱을 다시 열면 로컬 악보·페이지와 저장된 필기를 복구합니다.
- **분리된 팀 레이어 예시:** 읽기 전용 팀 메모가 다른 버전이나 페이지에 섞이지 않는 구조를 보여 줍니다. 실제 동기화 서비스는 아닙니다.

[실제 앱 화면](README.md#actual-app-screens)은 합성 악보와 분리된 테스트 저장소에서 촬영했습니다. [고급 UI 시안](docs/ui-concepts/README.md)은 후속 단계의 디자인 제안입니다.

## 연주자의 타이밍을 지킵니다

- 곡 안내는 **화면으로만** 표시합니다. 소리·진동은 사용하지 않으며, 다음 곡은 연주자가 직접 눌러 엽니다. 안내 수신이나 재연결만으로 현재 악보를 바꾸지 않습니다.
- 페이지는 각자 넘깁니다. 페이지 동기화나 자동 따라가기는 제공하지 않습니다.
- 최신 대기 안내만 표시하고 최근 10개 안내 기록은 별도로 둡니다. 연결이 끊긴 동안 놓친 안내를 자동 재생하지 않습니다.
- 검색·미리보기·업로드만으로 곡 안내가 발송되지 않습니다. 밴드마스터가 준비 후 명시적으로 안내합니다. 새 악보의 온라인 공유·수신에는 연결이 필요합니다.
- PDF 버전은 불변 원본으로 남깁니다. 필기 자동 병합이나 임의 좌표 맞추기는 하지 않습니다.
- 개인 필기와 팀 필기는 별도 레이어입니다. 팀 필기는 해당 순서 항목·정확한 버전·페이지가 일치할 때만 겹쳐 표시하고, 다른 버전에서는 팀 악보를 미리봅니다. 지난 예배의 지시를 다음 예배에 자동으로 덧씌우지 않습니다.
- 키 이름을 바꿨다고 PDF 코드나 음표가 조옮김되는 것은 아닙니다.

현재는 로컬 개발용 사용자 식별자를 사용합니다. 계정, 교회 멤버십, 게스트 초대와 서버에서 강제하는 개인 정보 접근 제어는 구현·검증이 필요합니다.

## 다음 단계

로컬 주간 준비 기능을 검증한 뒤 **비공개 교회·팀 라이브러리와 다운로드 → 함께 보는 손필기 → 화면으로 받는 곡·키 안내 → 실제 리허설 검증** 순서로 진행합니다. 팀의 동그라미·화살표·손필기는 첫 파일럿의 핵심 요구 사항입니다.

이번 피드백에서 강조한 주간 합본 PDF는 현재 내보내기와 구분해 구현·검증할 요청 기능입니다. 페달과 얼굴·동작 인식 페이지 넘김은 후속 검토로 남깁니다. 별도 채팅 기능은 첫 파일럿 범위에 추가하지 않습니다. 구체적인 개발 순서와 수용 기준은 [마일스톤 계획](docs/12_BUILD_PLAN.md)과 [확정 결정](docs/02_DECISIONS.md)을 따릅니다. 서버, 결제, 공개 배포는 활성화되어 있지 않습니다.

## 개발 및 검증

최소 배포 대상은 **iPadOS 16.0**입니다. 현재 실제 테스트 기기는 **iPad 6세대, iPadOS 17.7.11**이며, 기존 16.7.16 iPad와 Apple Pencil 실물 검증은 아직 남아 있습니다.

현재 네이티브 전체 검사에서 **18개 통과, 실패 0개, 비공개 PDF 입력 없이 실행한 1개 건너뜀**을 기록했습니다. 한국어 검색·즐겨찾기·버전 선택·예정곡/대기곡·파일 확인·재실행 UI 워크플로도 통과했습니다. 로컬 라이브러리 8개, 핵심 규칙 55개, Python 참조 검사 32개와 필기 검사 9개 그룹이 통과했고, Xcode 27 Release 빌드가 성공했습니다. 실제 편곡 악보의 새 네이티브 검사와 PDF 공유 화면 검사도 통과했습니다. 다른 UI 경로의 최종 검증 상태는 [M1 기록](verification/M1.md)을 확인하세요. Xcode 26.6의 자산 컴파일 제한은 과거 기록에 보존합니다.

추가로 실제 편곡 악보 2개를 사용한 네이티브 검사 1개와 손가락 UI 워크플로 1개가 iPadOS 17.7.11에서 통과했습니다. 편곡자의 PDF 주석 보존, 서로 다른 페이지 크기, 직접 위치·크기를 정하는 메모 복사, 실행 취소·다시 실행과 재실행 복구를 확인했습니다. 원본과 화면 캡처는 로컬에만 보관합니다. [검증 기록](verification/M0-private-pdf-pair.md) · [비공개 악보 테스트 방법](docs/PRIVATE_PDF_TESTING.md)
