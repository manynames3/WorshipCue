# WorshipCue native iPad design concepts

Generated 2026-10-07 with the built-in image generation tool. These are **potential UI designs**, not screenshots, verified device behavior, or implemented milestone claims. The score notation is illustrative synthetic content.

## 01 · Calm music stand

`01-calm-music-stand.png` — light reading surface, restrained native chrome, readable PDF as the main focus. The persistent new-song strip labels the pending announcement separately from the currently open v1 chart and requires an explicit tap. Local save uses a device/check icon. Wrong-version team notes appear as a preview action rather than drawn coordinates. Pencil tools and local page controls stay within reach.

This illustrates the eventual Music Stand with M4 announcements. M0 has no live call/backend implementation; the announcement strip is a design proposal. Today/Library navigation belongs to later milestones.

## 02 · Version and note transfer

`02-version-note-transfer.png` — charcoal surrounding chrome, paper remains readable, contextual version panel beside the chart. Copy only selected personal strokes, preserve the source version, manually drag/uniform-scale a destination preview, cancel or explicitly commit. Original-note preservation is a fixed lock/info state, never a checkbox. The v3 written key A is metadata for that immutable version and does not transpose the displayed v2/G sheet.

The production M0 slice implements selected-stroke transfer mechanics; the high-end contextual panel is a UI proposal. The archived-state/version-history presentation extends into M1.

## Prompt set

Initial generation briefs: (1) high-fidelity Korean native landscape iPad music stand, light reading mode, large paper area, calm explicit tap-to-open pending banner, exact-version team preview and local-only page controls; (2) premium charcoal native iPad version/notes panel, selected-stroke source preview, immutable v1→v2 transfer, manual uniform placement, cancel/confirm/undo. Both prompts explicitly prohibited automatic song/page following, note merging/migration, audio/haptics, transposition claims, billing/auth dashboards and real lyrics.

The final exact editing prompts are preserved in `final-prompts.json`. Built-in image generation/editing was used; no external CLI/API key. Output files were copied into this project, and originals were preserved at their generated-image paths.

Typography and icon geometry in these bitmaps are illustrative. Native implementation uses the project's Korean String Catalog and accessibility labels. These concepts do not reopen the fixed product decisions or mark native reliability gates passed.
