# iPad UX 명세

## 디자인 원칙
무대 위에서는 글자, 악보, 상태가 먼저입니다. 숨겨진 제스처에 핵심 기능을 맡기지 않습니다. 기본적으로 한국어, SF 시스템 글꼴, 큰 조작 영역, 차분한 시각 알림을 사용합니다. 제품 기본값: 일반 버튼 최소 44×44pt, 무대의 핵심 버튼 56pt 높이 이상. 색만으로 ‘내 필기/팀 필기/오프라인’을 구별하지 않습니다. 구체적 크기는 가장 작은 실제 iPad에서 다시 확인합니다.

흰 악보를 강제 색 반전하지 않습니다. 기본은 밝은 악보 + 어두운 주변 UI입니다. 네트워크 알림이 나타날 때 악보 영역이 갑자기 위아래로 이동하지 않도록 고정된 상태 공간을 확보합니다. Pencil이 화면에 닿아 있는 동안 새 패널이 자동으로 펼쳐지지 않습니다.

## S01. 오늘
```text
WorshipCue                         [교회/팀] [설정]
10월 11일 주일예배

[악보 열기]                     [예배 준비 확인]
준비된 악보 12/14 · 미완료 2개

1. 곡 A      연주 G · 팀 v2
2. 곡 B      연주 D · 팀 v1
3. 곡 A      연주 A · 팀 v3   ← 같은 곡의 별도 순서

[대기곡 18곡]          [링크/QR 공유]
밴드마스터에게만: [콘티 수정] [진행 맡기]
```
처음 사용자는 ‘샘플 예배’ 또는 ‘교회 초대 참여’로 시작합니다. 이미 내려받은 자료가 있으면 인증 갱신 실패 때문에 이 화면을 막지 않습니다. 사용자가 서버 권한을 잃었다는 사실이 확인되면 별도 권한 흐름을 따릅니다.

## S02. 악보장
```text
[콘티] 곡 A · 내 악보 v1 / G          1 / 2   [버전]
연결됨 · 마지막 확인 05:30
[밴드마스터 안내: 곡 B · D]                    [악보 열기]
────────────────────────────────────────────────────
                 악보 본문
           개인 필기 + 해당 팀 필기
────────────────────────────────────────────────────
[이전 페이지] [내 필기] [팀 필기 보기] [다음 페이지]
```
알림이 없으면 같은 높이 공간에 현재 확인한 연주 키를 작게 표시하거나 빈 공간을 유지합니다. 새 안내로 차트 프레임이 움직이지 않게 합니다. ‘소리 없음’ 안내를 반복하지 않습니다. 무음이 기본입니다.

미확인 안내의 곡/키는 배너에만, 현재 확인한 연주 키는 현재 악보 헤더에 표시합니다. 현재 악보가 A곡인데 최신 B곡의 G키를 A곡 헤더에 덮어쓰지 않습니다. 전체화면도 새 안내의 존재를 없애지 않습니다.

## S03. 밴드마스터 곡 준비
건반 앞에서 악보를 보며 여는 오른쪽 패널입니다. 이전 곡을 보던 화면은 유지됩니다.
```text
곡 준비  [닫기]
[검색: 초성 / 제목 / 별칭]
[대기곡] [최근] [즐겨찾기]

선택: 곡 B
팀 악보: v1 · 악보 D
연주 키: D
다운로드 상태: 이 기기 준비됨

[미리보기]                [팀에 곡 안내]
```
선택/미리보기/검색은 절대 안내하지 않습니다. ‘팀에 곡 안내’ 버튼만 발행합니다. 실수 이중 탭 방지를 위해 동일 command ID로 한 번만 처리하고 진행 중 비활성화합니다. 서버 응답이 없으면 ‘전송 확인 중’으로 표시하고 현재 상태를 조회합니다. 확인 없이 ‘보냈습니다’라고 표시하지 않습니다.

오프라인이면 발행 버튼 대신 ‘연결 후 안내할 수 있어요’를 표시합니다. 인터넷 복구 후 자동 발행하지 않습니다. 잘못 안내했을 때는 이전 안내를 몰래 삭제하지 않고 올바른 곡을 새로 안내합니다.

## S04. 새 곡 안내
배너는 가장 최근 안내 하나만 유지합니다. 확정 전까지 계속 보이되 접으면 헤더의 ‘새 곡 안내’ 칩으로 남습니다. ‘열기’가 주 동작이고 ‘알림 7개’ 같은 부담을 주지 않습니다.

터치가 시작된 뒤 안내가 바뀌는 경합: 동작은 화면에 렌더링된 call ID/sequence에 고정합니다. 이미 최신이 아니면 오래된 악보를 열지 않고 최신 배너로 갱신하며 ‘안내가 바뀌었습니다. 최신 곡을 확인해 주세요’를 표시합니다. 큰 확인 팝업은 쓰지 않습니다.

다운로드가 필요하면 배너 안에서 진행률과 취소를 표시하고 현재 악보를 그대로 둡니다. 다운로드가 끝났더라도 그 사이 새 안내가 왔다면 자동 전환하지 않습니다. 열리는 순간도 최신 call ID를 확인합니다. 최신 곡으로 바뀌면 다시 누르게 합니다.

## S05. 버전 선택과 필기 이동
```text
곡 A / 버전
v3 · A · 10/07 · 새 엔딩          [열기]
v2 · G · 10/06 · 3페이지         [열기]
v1 · G · 09/28 · 내 필기 있음     [열기]

[내 기본 악보로 설정]   [필기 옮기기]
```
‘열기’는 현재 보기만 변경합니다. ‘내 기본 악보로 설정’은 별도 명시적 선택입니다. 라이브 도중 버전 선택도 허용하되 팀 버전 차이를 명확히 표시합니다.

필기 이동 흐름: 원본 페이지에서 내 필기 영역 선택 → 복사 → 버전/페이지 선택 → 붙여넣기 미리보기 → 이동/균등 확대축소 → 완료. 원본은 항상 남습니다. 대상 원본 PDF도 수정하지 않습니다. 가로모드에서 원본/대상 나란히 보기가 가능하되 작은 화면에서는 단계형 전환을 제공합니다. 첫 파일럿은 여러 페이지 일괄 이동 없이 한 페이지씩 처리합니다.

## S06. 팀 필기
회원의 기본 필기 모드는 ‘내 필기’입니다. 진행권 보유자가 명시적으로 ‘팀 필기’로 전환하면 상단에 ‘팀 전체 공개’가 지속 표시됩니다. 페이지 이동 후에도 모드 표시가 유지됩니다. 개인/팀 지우개와 undo 기록은 독립적입니다.

다른 버전의 팀 필기:
```text
내 악보 v1 · 팀 악보 v3
팀 악보에 새 필기가 있습니다.      [팀 악보 보기]
```
미리보기는 원래 상태를 보존하는 읽기 전용 패널입니다. 해당 필기 페이지를 열어도 뒤의 개인 악보 페이지는 변하지 않습니다. ‘내 악보로 돌아가기’는 한 번에 닫습니다. 페이지가 작아 읽기 어려우면 미리보기만 확장하되 기존 악보 상태는 보관합니다. 미리보기를 열었다고 ‘현재 곡 열었음’으로 기록하지 않습니다.

## S07. 준비 확인
```text
예배 준비 확인
이번 콘티       4곡 / 팀 악보 + 내 악보
대기곡         18곡 / 팀 악보 + 내 악보

✓ 곡 A · 팀 v2 · 2.1 MB
✓ 곡 A · 내 v1 · 1.8 MB
! 곡 B · v1 · 다운로드 실패        [재시도]

[모두 다운로드]             준비 23/24개
```
모든 악보 원본 해시/파일이 검증되고 필요한 개인 필기 저장이 완료된 뒤에만 완료 상태를 표시합니다. 팀 필기는 ‘마지막 확인 시각’을 함께 표시합니다. 오프라인에서는 ‘다운로드 완료’와 ‘최신 팀 필기 확인’이 다를 수 있습니다.

## S08. 오프라인/재연결
‘오프라인 · 저장된 악보를 보고 있어요’는 현재 차트 위의 작고 고정된 상태 영역입니다. ‘마지막 수신 05:31’로 최신 여부를 분명히 합니다. 빈 화면이나 로그인 팝업을 자동으로 띄우지 않습니다. 재연결 후에도 ‘현재 열어둔 악보’와 ‘새 안내’를 구분하고 사용자의 탭을 기다립니다.

## S09. 최근 안내
최근 10개를 시간순 역순으로 보여줍니다. 과거 호출은 ‘지난 안내’라고 표시합니다. 과거 악보를 열어도 현재 안내를 확인한 것으로 처리하지 않습니다. 대기열을 순서대로 넘기는 UI는 만들지 않습니다.

## S10. 참여/진행 상태
밴드마스터에게 ‘연결됨’, ‘마지막 응답’, ‘안내 수신’, ‘악보 열었음’, ‘내 버전이 팀과 다름’을 보여줍니다. 마지막 이벤트가 오래되면 상태는 ‘확인 필요’입니다. 숫자를 ‘준비 완료’로 명명하지 않습니다. 연주자가 악보를 열었다고 음악적으로 준비된 것은 아닙니다.

## 오류 문구 원칙
원인 + 현재 보존된 것 + 한 가지 복구 행동을 제시합니다.
- ‘새 악보를 아직 받지 못했어요. 현재 악보는 그대로 볼 수 있어요. [재시도]’
- ‘이 기기에 저장했어요. 인터넷에 연결되면 개인 필기를 동기화할게요.’
- ‘같은 페이지의 다른 수정이 있어요. 두 버전 모두 보관했습니다. [비교]’
- ‘진행권이 변경되었습니다. 작성한 필기는 초안으로 보관했어요.’

## 접근성과 세부 상호작용
Dynamic Type은 도구/메타데이터에 적용하되 PDF 자체 레이아웃을 임의로 재구성하지 않습니다. 긴 한글 제목은 최대 두 줄, 전체 제목은 상세에서 확인합니다. 배너 버튼과 닫기 버튼의 탭 영역을 분리합니다. VoiceOver 라벨과 포커스 순서를 검증하고 새 안내로 현재 포커스를 빼앗지 않습니다. 알림 전달용 사운드/진동을 추가하지 않되 운영체제 접근성 도구의 사용자 설정을 막지 않습니다.

화면 회전은 지원합니다. 자동잠금 해제는 사용자가 시작한 예배 모드가 전경에 있을 때만 적용하고 종료/배경 전환 시 원복합니다. 마이크 권한은 요청하지 않습니다. 카메라 권한은 앱 내부 QR 스캔을 선택했을 때만 요청하고 코드/링크 대안을 제공합니다.
